# Admissibility Before Representation

## A Standalone Framework for Discovered State-Spaces, Relation Constraints, Ontological Fidelity, and Non-Arbitrary Cartography

---

# Status

This document extends:

```text
Capability Cartography

Resolution Before Navigation

State-Space Before Comparison
```

Its purpose is to prevent a deeper mistake:

```text
assuming that admissible dimensions,
relations,
coordinates,
or transitions
can be invented arbitrarily
```

The framework argues:

```text
representation may be invented

admissibility must be discovered
```

A map-maker may choose symbols freely.

Reality does not choose its structure freely.

The task of cartography is not to create admissibility.

The task is to discover it.

---

# Abstract

Most representational systems are highly permissive.

Examples:

```text
natural language

knowledge graphs

object-oriented programming

databases

ontologies
```

These systems allow almost unlimited statements.

For example:

```text
electron.favorite_pizza

Berlin.marital_status

rock.tax_bracket

photon.voting_system
```

can all be represented.

The ability to represent a statement does not imply that the statement corresponds to a meaningful coordinate in reality.

The framework therefore distinguishes:

```text
expressibility

representability

admissibility
```

A relation may be expressible.

A relation may be representable.

Yet still fail to be admissible.

Reality appears to constrain admissibility.

The purpose of cartography is to discover those constraints.

---

# 0. The Permissiveness Mistake

Many systems silently assume:

```text
if a relation can be represented,
then the relation exists
```

This is false.

Programming languages allow:

```python
electron.favorite_pizza = "margherita"
```

The runtime accepts it.

Reality does not.

The mistake is confusing:

```text
syntactic possibility
```

with:

```text
ontological possibility
```

A map may contain arbitrary symbols.

The terrain cannot contain arbitrary structure.

---

# 1. Expressibility Is Not Admissibility

The framework proposes:

```text
expressible
⊇
representable
⊇
admissible
```

Example:

```text
electron.favorite_color
```

is expressible.

It is representable.

It is not obviously admissible.

Example:

```text
electron.charge
```

is expressible.

It is representable.

It is admissible.

The distinction is critical.

A graph can contain infinitely many edges.

Reality cannot contain infinitely many meaningful relations for a given object.

---

# 2. State-Spaces Are Discovered

A common assumption is:

```text
state-spaces are invented
```

The framework proposes the opposite.

State-spaces are discovered.

For example:

```text
electron
```

appears to possess coordinates such as:

```text
position

momentum

spin

charge

energy
```

These were not invented.

They were discovered.

Physics did not create electron spin.

Physics discovered that spin was required to explain observations.

The map adapted to reality.

Reality did not adapt to the map.

---

# 3. Degrees Of Freedom Are Constraints

A degree of freedom is often treated as:

```text
an available variation
```

But it is equally:

```text
a limitation
```

If a system possesses:

```text
N
```

degrees of freedom,

then it lacks every degree of freedom outside those coordinates.

For example:

```text
electron
```

does not appear to possess:

```text
political preference

legal identity

metabolic state

language
```

Not because these properties are hidden.

But because the state-space does not support them.

Absence is structural.

Not merely unknown.

---

# 4. Reality Is Not An Arbitrary Graph

Many graph systems begin with:

```text
Node

Edge
```

and permit arbitrary edge creation.

Example:

```text
Berlin
--friend_of-->
bicycle
```

The graph accepts this.

Reality may not.

The framework therefore proposes:

```text
Node

State-Space

Dimension

Relation Type

Admissibility Constraint
```

Relations are not primitive.

Relations are constrained.

---

# 5. The Admissibility Principle

A relation is admissible only if:

```text
the participating entities support it

the state-space supports it

the required dimensions exist

the relation preserves meaning

the relation survives resolution analysis
```

Otherwise the relation remains:

```text
syntactic

speculative

analogical

or undefined
```

---

# 6. Undefined Is A Real Outcome

Many systems collapse all questions into:

```text
true

false
```

The framework requires:

```text
undefined
```

Example:

```text
electron.voting_system
```

The result is not:

```text
false
```

The result is:

```text
undefined
```

because:

```text
voting_system
```

is not an admissible coordinate of the represented state-space.

Undefined is often more informative than false.

---

# 7. Discovery Versus Invention

Maps are invented.

Terrain is discovered.

The distinction must remain visible.

For example:

```text
longitude
```

is partly invented.

The Earth is not.

The coordinate system is chosen.

The underlying structure is not.

Similarly:

```text
charge
```

is a human label.

The phenomenon being tracked is not.

A good map discovers useful coordinates.

A bad map invents coordinates without discovering whether reality supports them.

---

# 8. Why Google Maps Works

A geographic map succeeds because it does not permit arbitrary structure.

A city possesses:

```text
boundaries

roads

buildings

districts

transport networks
```

A routing system can therefore construct:

```text
contains

adjacent_to

connected_to

route_through
```

The system does not freely create:

```text
enzyme_activity

marital_status

spin_state
```

for cities.

The map is useful because admissibility is constrained.

---

# 9. Conceptual Cartography Has The Same Requirement

Conceptual mapping faces a larger domain.

Examples:

```text
mind

market

fish

AGI

government

memory

institution
```

The temptation is to permit unrestricted relations.

The framework rejects this.

The challenge is not:

```text
creating more edges
```

The challenge is:

```text
discovering admissible edges
```

---

# 10. Relation Discovery

A relation should be treated similarly to a scientific hypothesis.

Initially:

```text
possible relation
```

Then:

```text
supported relation
```

Then:

```text
admissible relation
```

Relations are not granted legitimacy merely because they can be named.

They require support from the represented system.

---

# 11. The Finite Relation Thesis

The framework proposes:

```text
every represented system
possesses only a finite set of admissible relation types
at a given resolution
```

The exact number may be unknown.

But it is not arbitrary.

For example:

```text
electron
```

does not possess an unlimited number of meaningful dimensions.

Neither does:

```text
city

fish

human

AGI
```

The cartographic task is discovering those limits.

---

# 12. Resolution Changes Admissibility

Admissibility depends on resolution.

Example:

```text
human
```

At one resolution:

```text
mass

position

velocity
```

At another:

```text
memory

goals

beliefs
```

At another:

```text
citizenship

institutional role

legal rights
```

A coordinate may be admissible at one resolution and undefined at another.

The map must record this.

---

# 13. Admissibility Before Comparison

Before comparison ask:

```text
Which dimensions are admissible?
```

Not:

```text
Are these the same category?
```

Category systems often hide admissibility.

State-space analysis exposes it.

---

# 14. Admissibility Before Navigation

Before navigation ask:

```text
Which transitions are admissible?
```

Not:

```text
Can I imagine the destination?
```

Imagining a state does not imply reachability.

Reachability requires admissible paths.

---

# 15. Admissibility Before Optimization

Optimization assumes:

```text
objective

path

state-space
```

all already exist.

Often they do not.

Optimization therefore comes late.

Before optimization:

```text
discover dimensions

discover relations

discover constraints

discover admissible transitions
```

Only then can optimization begin.

---

# 16. Ontological Humility

The framework implies a form of humility.

Maps are negotiable.

Reality is not.

The purpose of cartography is not:

```text
creating possibilities
```

The purpose is:

```text
discovering admissible possibilities
```

A powerful representational system can describe infinitely many worlds.

Reality appears to instantiate only a constrained subset.

The task is not maximizing expression.

The task is identifying which expressions correspond to admissible structure.

---

# 17. Final Compression

A weak cartography asks:

```text
What can be represented?
```

A stronger cartography asks:

```text
What is admissible?
```

A weak ontology asks:

```text
What relations can be named?
```

A stronger ontology asks:

```text
Which relations are supported by reality?
```

A weak graph allows arbitrary edges.

A stronger graph discovers constrained edges.

Therefore:

```text
state-spaces are discovered before they are represented

relations are discovered before they are asserted

admissibility is discovered before comparison

admissibility is discovered before navigation

admissibility is discovered before optimization
```

The central principle is:

```text
reality is not an arbitrary graph

the map may be invented

the admissible structure must be discovered
```
