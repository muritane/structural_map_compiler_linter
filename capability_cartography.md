# Capability Cartography

## A Framework for Mapping Admissible Reachability

### From Capability Graphs to Capability Maps

---

# Status

This document revises and extends the Edge-Generating Capability Graph framework.

The central shift is subtle but important.

The original framework emphasized:

```text
edge generation
```

This document argues that a deeper primitive may be:

```text
capability cartography
```

The purpose of a map is not to invent terrain.

The purpose of a map is to discover, represent, validate, and navigate terrain that actually exists.

Likewise:

```text
a capability map
is not a catalog of imagined possibilities

it is a map of admissible reachability
```

The map should remain faithful to reality.

A useful map distinguishes:

```text
known

unknown

reachable

unreachable

blocked

hypothetical

impossible
```

without confusing them.

---

# Core Thesis

Traditional planning asks:

```text
What is the best route?
```

Capability cartography asks:

```text
What terrain exists?

What destinations exist?

Which transitions are admissible?

Which transitions are blocked?

Which transitions are merely imagined?

What must be discovered?

What must be built?
```

The primary task is not optimization.

The primary task is:

```text
reachability discovery
```

---

# 0. Maps Do Not Invent Terrain

A road map does not contain:

```text
teleportation

dragon flight

walking through mountains

driving across oceans
```

even if someone imagines such possibilities.

The map remains useful because it represents:

```text
roads

bridges

ferries

paths

railways

air routes
```

that actually exist.

The same principle should apply to capability systems.

A capability map should not represent:

```text
all imaginable transformations
```

It should represent:

```text
all admissible transformations
```

under the currently modeled reality.

---

# 1. Capability Space Is Terrain

Physical maps describe terrain.

Capability maps describe transformation terrain.

Examples:

```text
untrained
→ trained

ill
→ healthy

village
→ connected village

raw material
→ finished product

mortal
→ cultivator

student
→ engineer
```

Each transition occupies capability terrain.

The terrain determines:

```text
what transitions exist

what transitions are difficult

what transitions require support

what transitions are impossible
```

---

# 2. Unknown Nodes Often Appear Before Edges

Many theories assume:

```text
states
+
edges
```

are already known.

Reality often develops differently.

First:

```text
new state becomes visible
```

Then:

```text
reachability becomes uncertain
```

For example:

```text
Village A
↔
Village B
```

A traveler reports:

```text
Village C exists
```

Now the system knows:

```text
A

B

C
```

but does not know:

```text
B → C
```

The immediate question becomes:

```text
Can C be reached?
```

This is the origin of cartography.

Maps grow because destinations become visible before routes become known.

---

# 3. Reachability Resolution

When a new node appears, the system attempts to resolve reachability.

Possible outcomes include:

```text
edge discovered
```

Example:

```text
mountain pass exists
```

or:

```text
edge constructed
```

Example:

```text
bridge built
```

or:

```text
edge impossible
```

Example:

```text
physical law forbids transition
```

or:

```text
edge remains unknown
```

because evidence is insufficient.

The map should preserve these distinctions.

---

# 4. Discovery And Construction Are Different

A critical distinction:

```text
discovering an edge
```

is not identical to:

```text
creating an edge
```

Examples:

```text
hidden trail
```

already exists.

The edge is discovered.

```text
new bridge
```

does not exist.

The edge must be constructed.

Both increase reachability.

But they are fundamentally different processes.

---

# 5. Admissible Reachability

The map should only contain transitions that are admissible.

Admissibility means:

```text
the transition can actually occur
under the rules of the modeled reality
```

Admissibility may depend on:

```text
physics

biology

tools

resources

infrastructure

institutions

permissions

knowledge
```

An admissible edge is not necessarily easy.

It is merely possible.

---

# 6. Reality Defines The Map

Every capability map is anchored to a reality model.

The first question is always:

```text
What kind of world is this?
```

Before route planning.

Before optimization.

Before capability acquisition.

The map must establish:

```text
which transformations are valid
```

within the modeled universe.

---

# 7. The Cultivation Example

Cultivation stories reveal this process clearly.

The protagonist's first question is rarely:

```text
How do I reach the highest realm?
```

The first question is:

```text
Does cultivation exist?
```

That is a reachability question.

Specifically:

```text
mortal
↓
cultivator
```

Is this transition admissible?

If:

```text
no
```

the entire cultivation graph disappears.

If:

```text
yes
```

a new capability region becomes visible.

Only then does exploration begin.

# 9. Ceilings And Horizons

Every explored region appears to have limits.

Examples:

```text
maximum mountain

edge of empire

highest cultivation realm

largest known civilization
```

These become:

```text
known ceilings
```

The important distinction is:

```text
known ceiling
≠
actual ceiling
```

Many capability expansions occur because previously assumed boundaries are discovered to be local rather than global.

Examples:

```text
continent
↓
planet

planet
↓
solar system

mortal
↓
immortal

immortal
↓
higher realm
```

Capability cartography continually tests whether apparent boundaries are genuine.

---

# 10. Constraints Define Terrain

Maps are shaped by constraints.

Examples:

```text
gravity

oxygen requirements

energy availability

institutional rules

resource scarcity

legal restrictions
```

Constraints determine:

```text
which edges exist

which edges fail

which edges require support
```

Without constraints:

```text
all destinations appear equally reachable
```

which destroys navigational value.

---

# 11. Supports Are Infrastructure

Some transitions exist only because supports exist.

Examples:

```text
river crossing
+
bridge
```

```text
flight
+
aircraft
+
airport
```

```text
medical treatment
+
hospital
```

Supports are not destinations.

Supports are terrain modifications.

They change admissible reachability.

# 12. Capability Acquisition As Exploration

Learning becomes a cartographic process.

The learner discovers:

```text
new distinctions

new constraints

new regularities

new invariants

new routes
```

Expertise is often:

```text
seeing terrain others cannot see
```

The expert perceives:

```text
hidden paths

blocked paths

dangerous paths

shortcut paths
```

that novices miss.

---

# 13. Civilization As Collective Cartography

Civilizations continuously expand capability maps.

Examples:

```text
discover continent

map continent

build roads

build ports

build railways

build internet

build institutions
```

Each step expands reachability.

Civilizational progress can therefore be viewed as:

```text
progressive expansion
of validated reachability
```

rather than accumulation of isolated facts.

---

# 14. Capability Maps Versus Possibility Catalogs

A possibility catalog asks:

```text
What could be imagined?
```

A capability map asks:

```text
What can actually be reached?
```

This distinction preserves conceptual integrity.

The map remains tied to reality.

It does not become fantasy.

---

# 15. The Primary Operation

Traditional planners perform:

```text
path search
```

Capability cartographers perform:

```text
reachability resolution
```

Given:

```text
known state
```

and

```text
new state
```

the system asks:

```text
Can the destination be reached?
```

If yes:

```text
discover route
```

If not:

```text
identify blocker
```

If support can be added:

```text
construct route
```

If constraints forbid it:

```text
mark impossible
```

This process continuously expands map fidelity.

---

# 16. Intelligence As Cartography

A route planner assumes:

```text
terrain already known
```

A cartographer discovers:

```text
terrain itself
```

A capability cartographer discovers:

```text
reachable transformations
```

under real constraints.

Intelligence therefore becomes:

```text
the progressive discovery,
validation,
construction,
and navigation
of admissible reachability.
```

---

# Final Compression

A map begins with:

```text
known territory
```

New destinations appear.

Some routes already exist.

Some routes must be discovered.

Some routes must be built.

Some routes are permanently blocked.

Capability is therefore not merely:

```text
having skills
```

Capability is:

```text
occupying a position
within a reachability landscape.
```

Learning reveals terrain.

Science reveals terrain.

Exploration reveals terrain.

Infrastructure reshapes terrain.

Civilization expands terrain.

A powerful system is not one that imagines unlimited possibilities.

A powerful system is one that accurately discovers what transformations are admissible, what transformations are impossible, where the boundaries truly lie, and what must be done to expand reachable territory.

Capability is cartography.

Generality is broad, reliable navigation across discovered capability terrain.

Intelligence is the continual refinement of the map.
